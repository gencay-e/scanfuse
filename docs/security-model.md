# Security Model

`scanfuse` is an offline command-line utility that imports pentest scanner outputs (Nmap, Nuclei, OWASP ZAP, Burp Suite, Nessus, Trivy, SARIF, Semgrep, Grype, Nikto and testssl.sh), deduplicates findings, and exports unified reports as Markdown, standalone HTML, JSON, CSV, SARIF or PDF.

## Deployment Context

* Runs as a local single-user CLI process (`scanfuse/cli.py`).
* Performs local file I/O only. It opens no network sockets and makes no outbound HTTP or DNS requests.
* Processes scanner output files that frequently contain attacker-controlled strings captured from scanned targets (HTTP banners, headers, responses, TLS subject names, and reflected payloads).

## Trust Boundaries and Inputs

### Untrusted Inputs

* **Scanner input files** (`file_path` arguments and `stdin` in `scanfuse/cli.py`, parsed by `scanfuse/parsers/*.py`):
  * XML inputs (`nmap.py`, `zap.py`, `burp.py`, `nessus.py`, `nikto.py`) and JSON/JSONL inputs (`nuclei.py`, `trivy.py`, `sarif.py`, `semgrep.py`, `grype.py`, `nikto.py`, `testssl.py`) are untrusted. Nikto CSV inputs are also untrusted. Both the file structure and all embedded text fields (`title`, `description`, `remediation`, `host`, `evidence`, `references`, `identifiers`) may be attacker-controlled.

### Trusted Operator Inputs

* **Command-line arguments** (`--output`, `-f`/`--format` (input format), `--format-out`, `--min-severity`, `--host`, `--template-dir`, `--replace`, `--csv-excel`, `--config`, `--baseline`).
* **Local configuration file** (`.scanfuse.yaml` in the current working directory or the file selected by `--config`, loaded with a strict `yaml.SafeLoader` subclass in `scanfuse/config.py`). Configuration affects filtering and report contents; malformed or invalid configuration marks the run incomplete.
* **Baseline JSON report** (`--baseline`): the operator selects a complete schema version 2 report. Its contents affect retest statuses and must come from the same scope and filters; comparison does not authenticate the report. An incomplete current run does not mark findings resolved.
* **Custom Jinja2 templates** (`--template-dir`, loaded by `ScanfuseEngine._template_env` in `scanfuse/engine.py`).

## Security Invariants

1. **No XML External Entities (XXE) or Entity Expansion:**
   All XML parsing in `scanfuse/parsers/nmap.py`, `zap.py`, `burp.py`, `nessus.py` and `nikto.py` uses `defusedxml.ElementTree` (`iterparse` or `fromstring`), which rejects external entities and entity expansion (`DefusedXmlException` is caught in `ScanfuseEngine.process_file`) and never fetches or resolves external DTDs (`forbid_external=True`). Internal DTD declarations (such as those generated by Burp Suite) are permitted by `defusedxml`'s default settings without external network or filesystem access.
2. **HTML Sanitization in Standalone Reports:**
   All Markdown fragments rendered into `report.html` pass through `nh3.clean` in `scanfuse/html_report.py` (`render_report_fragment`), restricting tags to `REPORT_TAGS` (`a`, `b`, `blockquote`, `br`, `code`, `del`, `div`, `em`, `h1`–`h6`, `hr`, `i`, `li`, `ol`, `p`, `pre`, `s`, `strong`, `table`, `tbody`, `td`, `th`, `thead`, `tr`, `ul`), attributes to `a[href]` and `a[title]`, and URL schemes to `http`, `https`, and `mailto`.
3. **Markdown Escaping and Fence Isolation:**
   * Scalar fields (`title`, `ip`, `hostname`, `os`, `source_tool`, `port`, `identifiers`, and the host, `method`, and `location` of each observation) pass through the `md` filter (`md_escape` in `scanfuse/engine.py`) so they cannot introduce HTML tags, Markdown links, lists, or headings.
   * Free-text fields (`description`, `remediation`) pass through `mdtext` (`md_text` in `scanfuse/engine.py`), which HTML-escapes raw `<`, `>`, and `&` and escapes heading markers outside fenced code blocks. Fenced blocks remain intact for code rendering, and the final HTML still passes through `nh3.clean`.
   * Reference URLs pass through `md_reference`: HTTP(S) URLs with a network location are percent-encoded inside autolink brackets; all other values are escaped as plain text.
   * Evidence blocks use `code_fence` (`fence` filter) to select a backtick fence strictly longer than any backtick run in the payload.
4. **Spreadsheet Formula Neutralization (CSV Injection):**
   Every cell written by `ScanfuseEngine.export_csv` passes through `csv_safe` (`scanfuse/engine.py`). It normalizes text with `NFKC`, skips leading whitespace, formatting/BOM characters (`\ufeff`, `\u200b`–`\u200d`, `\u2060`, `\u00a0`), and Unicode control characters when detecting a leading `=`, `+`, `-`, or `@`, and prepends a single quote (`'`) whenever such a formula indicator is found or the raw cell starts with `\t`, `\r`, `\n`, space, or `\ufeff`. Plain values starting only with `\u00a0`, `\u200b`, or `\v` (without a following formula indicator) are not modified.
5. **Safe Output File Names and Staged Publishing:**
   * Finding slugs come from `unique_slug` (`scanfuse/utils.py`), which limits characters to `[a-z0-9-]`, enforces a 100-character limit including any `-N` suffix, and rejects `RESERVED_SLUGS` (`index`, `report`, `con`, `prn`, `aux`, `nul`, `com1`–`com9`, `lpt1`–`lpt9`).
   * `ScanfuseEngine._publish` stages writes in a temporary directory first, refuses to overwrite existing files without `--replace`, and on `--replace` removes stale files only when they appear in `.scanfuse-manifest-<kind>.json` as plain file names (not dotfiles or paths) with a matching SHA-256 digest. Manifest entries without digests remain untouched. Because the manifest is unauthenticated, anyone with write access to the output directory can alter it.
6. **SARIF and PDF Output:**
   `report.sarif` is serialized with `json.dumps` so scanner strings cannot break JSON structure. `report.pdf` (`scanfuse/reporters/pdf.py`) renders plain text via `fpdf2` with no interactive annotations, embedded files, or scripts, and writes directly without a manifest file.

## Verification Scope

Browser tests run in headless Chromium against generated `report.html` controls and untrusted payloads. Spreadsheet tests run Power Query formula-import checks when Windows Excel is available. These checks do not cover every browser or spreadsheet client.

## In-Scope Vulnerability Classes

* **XXE or XML entity expansion** bypassing `defusedxml` in `scanfuse/parsers/*.py`.
* **Cross-Site Scripting (XSS)** in generated `report.html` via crafted scanner fields bypassing `md_escape`, `md_text`, `code_fence`, or `nh3.clean` (`scanfuse/engine.py`, `scanfuse/html_report.py`).
* **Path traversal or arbitrary file overwrite** outside `--output` triggered by crafted finding titles, slugs, or manifest entries (`scanfuse/utils.py`, `scanfuse/engine.py`).
* **CSV formula injection** bypassing `csv_safe` (`scanfuse/engine.py`).
* **Unsafe deserialization** in configuration or parser loading (e.g., replacing the safe configuration loader with an unsafe loader).

## Out of Scope / Non-Issues

* **Jinja2 `autoescape=False` in `ScanfuseEngine._template_env` (`scanfuse/engine.py`):**
  Jinja2 renders Markdown templates (`finding.md.j2`, `index.md.j2`), not HTML directly. Escaping is enforced explicitly via the `| md`, `| mdtext`, and `| fence` template filters, and the resulting HTML is sanitized by `nh3.clean` in `scanfuse/html_report.py`.
* **Malicious custom templates passed via `--template-dir` or local `.scanfuse.yaml`:**
  The CLI user running `scanfuse` and choosing `--template-dir` or `.scanfuse.yaml` already executes with their own local user privileges.
* **Scanner URLs in `references` or `description` pointing to external phishing/malicious sites:**
  Preserving `http://` and `https://` links reported by scanners is intended behavior (documented in `SECURITY.md`); only non-web schemes such as `javascript:` or `data:` are in scope.
* **Memory exhaustion on multi-gigabyte single-line inputs:**
  Local resource consumption from oversized local files passed by the operator is a known operational limit, not a privilege boundary violation.
